# recipes/ — 成品参数存档

## 为什么需要它

`.xmp` 预设存的是**可复用的风格**。但有些东西是**照片专属**的，存不进预设：

- 这张照片当时用的是**哪个色温**（现场光专属）
- **裁切**的具体数值
- **局部调整**打在哪里
- 当时**为什么**这么调

三个月后你回看一张满意的照片，想「再来一次」，光有预设是不够的。**`recipes/` 就是干这个的。**

另一个用途：**调试和复盘**。当你发现某张照片「重建后对不上原版」时，一份完整的参数存档能让你快速定位是哪个参数漂了（我们踩过这个坑——见 [坑 19](../docs/pitfalls.md#pit-19)）。

---

## 格式

一张照片一个 YAML 文件，见 [`TEMPLATE.yaml`](TEMPLATE.yaml)。

命名：`YYYY-MM-DD-<简短描述>.yaml`，例如：

```
recipes/
├── TEMPLATE.yaml
├── 2026-10-14-黄昏街头.yaml
└── 2026-10-14-夜街小巴.yaml
```

---

## 怎么生成

**自动生成**（推荐）：用 `scripts/lr_catalog.py` 直接把参数导出成 YAML 骨架：

```powershell
# Lightroom 关着时最可靠（运行时不实时落盘，见 setup.md 第六节）
python scripts/lr_catalog.py dump <照片id>
```

然后手工补上「为什么这么调」——**这部分才是三个月后最有价值的内容**，脚本生成不了。

---

## ⚠️ 存档不等于可复现

**别指望照着一份 YAML 就能 100% 还原当时的渲染。** 我们实测过：

重建时按「正确的」原始色温 3800K 写入，结果与当时的批准版差了 **MAD 8.0**。原因是当时的批准版其实是在**被 bug 卡住的 3400K** 下调出来的（见 [坑 10](../docs/pitfalls.md#pit-10)）——**记录的真实值 ≠ 当时的实际值**。

所以规矩是：

> **唯一的真相来源是渲染文件，不是参数。**
> 每次定稿，把当时的导出**另存到一个不会被覆盖的路径**，交付前用 MAD 比对（见 [README](../README.md#交付前必须做的验证)）。
> `recipes/` 里的 YAML 是**给人看的说明书**，不是**给机器执行的构建脚本**。

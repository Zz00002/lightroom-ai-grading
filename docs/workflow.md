# 单张精调工作流

这份文档解释**为什么**是这个顺序。给 AI 看的可执行版本在 [`SKILL.md`](../SKILL.md)。

我们试过的工作方式里，**只有「单张精调」是真正有效的**。

不是「把 500 张照片批量套一个风格」——那是滤镜，不是修图。真正有价值的是：**你从一堆照片里挑出几张值得调的，然后把这几个调到你要的感觉。** 这个过程需要反复看、反复判断、反复微调，而 AI 恰好擅长做那个不知疲倦的执行者。

---

## 全流程

```
┌─ 准备 ──────────────────────────────────────────┐
│  环境检查（doctor.py）→ 插件通了吗               │
└─────────────────────────────────────────────────┘
                    ↓
┌─ 理解 ──────────────────────────────────────────┐
│  定位照片 → 看图 → 读用户原有参数                │
│  ⚠️ 不看就调必翻车                               │
└─────────────────────────────────────────────────┘
                    ↓
┌─ 保护 ──────────────────────────────────────────┐
│  建虚拟副本 → 选中 → （可选）复位                │
│  原片永不修改                                    │
└─────────────────────────────────────────────────┘
                    ↓
┌─ 曝光 ──────────────────────────────────────────┐
│  看 p50 → 修到 110~160                           │
│  ⚠️ 这一步不做好，后面全是白干                   │
└─────────────────────────────────────────────────┘
                    ↓
┌─ 风格 ──────────────────────────────────────────┐
│  色调曲线分通道（主力）→ HSL 八区 → 基础滑块     │
└─────────────────────────────────────────────────┘
                    ↓
┌─ 局部 ──────────────────────────────────────────┐
│  HSL 优先 → add_local_adjustment（线性/径向）    │
│  ⚠️ 不要用 add_ai_mask                           │
└─────────────────────────────────────────────────┘
                    ↓
┌─ 收尾 ──────────────────────────────────────────┐
│  高 ISO 降噪 / 暗角 / 颗粒                       │
└─────────────────────────────────────────────────┘
                    ↓
┌─ 交付 ──────────────────────────────────────────┐
│  全尺寸导出 → MAD 比对参照文件 → 存档            │
└─────────────────────────────────────────────────┘
```

## 阶段 1 · 理解：动手前必须先看

### 1.1 看图（不可跳过）

**不看就调，必翻车。** 光线条件、构图、内容决定**风格可不可行**。

- 优先用**导出到文件 + 读文件**（可靠）
- `get_photo_preview` 经常 90 秒超时，见 [坑 2](pitfalls.md#pit-2)

### 1.2 读用户原有的参数（价值极高）

用户原来的参数**暴露了他的审美意图**。这是你唯一的、免费的、关于「他喜欢什么」的一手情报。

| 观察到 | 推断 |
|---|---|
| `Highlights −77 / Shadows +45` | 很在意高光溢出，坚持打开暗部 |
| `Temperature 6250K` 对着阴天 | 在对抗现场冷光 |
| `HueAdjustmentAqua +67 / Blue +46` | 想把青蓝推向**紫**（冷紫调） |
| `Blacks −63` + 暗角 `−30` | 重对比的硬朗纪实感 |

**但照搬不行**——用户可能就是**因为不满意**才让你调的。

**完全无视更糟**——你会做出一个他明确不想要的风格，还觉得他不懂欣赏。

> 💡 **正确做法：先读懂，再问他**——「延续你原来的方向」还是「基本重调」。

## 阶段 2 · 保护：原片永不修改

```
create_virtual_copies([源id])    → 拿到新 id
select_photos([新id])            ← 必须！复位只作用于「当前活动照片」
reset_develop(新id, scope="all") → 看 before/after diff，不要看 success
```

**为什么要虚拟副本**：你随时可能想推翻重来。而且用户可能同时想要一版自己的、一版你的——虚拟副本让两个版本共存于同一张原片之下。

**复位是可选的**：如果用户的调整只是「差一口气」，在他的基础上改，比从头做更尊重他的意图，也通常更快出结果。

> ⚠️ `reset_develop` 会**静默失败**并返回 `success: true`。判断依据是响应里的 `before`/`after` 是否相同。见 [坑 3](pitfalls.md#pit-3)。

## 阶段 3 · 曝光优先（最重要的一步）

**先看 `p50`。**

| p50 | 判断 | 动作 |
|---|---|---|
| < 110 | 偏暗 | 提亮 |
| **110 ~ 160** | ✅ 正常 | 进入风格阶段 |
| > 160 | 偏亮 | 压一点 |
| > 180 | **过曝** | **必须先把曝光修好** |

### 为什么这一步不能跳过

我们实测过：一张 `p50 = 195`（一半画面比 195 还亮）的照片，被直接调成「冷青电影感」。肉眼觉得「差不多了」，**直方图打脸**：

- 死白 **12.4%**（健康值应 < 8%）
- 天空 R−B 只有 **−4**（基本中性，说明**冷调根本没落地**）

**根因**：在已经发白的底子上刷冷调，只会从「干净的白」变成「浑浊的灰白」。

修正曝光后重调，死白降到 **7.7%**、天空 R−B 到 **−12**——这才是真的冷青。

> ⚠️ **对比度和黑阶只能修暗的那一端。** 它们动不了占画面大头的亮部。不要指望用它们救过曝。

## 阶段 4 · 风格：曲线是主力

### 按威力排序的四种手段

#### 1️⃣ 色调曲线分通道 ← 最强，且是做冷暖分离的唯一有效手段

| 通道 | 做法 | 效果 |
|---|---|---|
| **蓝** | 暗部抬 + 高光压 | 暗部偏青蓝、亮部去蓝 |
| **红** | 暗部压 + 高光抬 | 阴影去红、高光转暖 |
| **绿** | 暗部微抬 | 让阴影落在青绿而非纯蓝 |

曲线能**精确控制过渡**，比任何分级滑块都细腻。

#### 2️⃣ HSL 八区 ← 精准打击特定颜色

两个用途：**压掉抢眼的杂色**（霓虹招牌）、**保住肤色**。

> 💡 **进阶用法**：当画面里有**一种独占某个颜色的主体**时（例如红车身 vs 满画面的黄格线），直接调那个颜色的 HSL，**效果等同于局部调整，而且零蒙版风险**。

#### 3️⃣ 基础滑块（曝光 / 高光 / 阴影 / 黑阶 / 对比 / 去朦胧）

粗调。**`Dehaze` 慎用**——它算暗通道先验，对阴天天空是灾难。实测 `+12` 让死白从 6.2% 涨到 12.4%。

#### 4️⃣ 白平衡 ← **慎用**

它影响**全局肤色**。风格化**优先靠曲线，不要靠色温**。

> ⚠️ 而且 `WhiteBalance: "As Shot"` **不会**还原色温——见 [坑 10](pitfalls.md#pit-10)。要改色温就**显式写死数值**。

## 阶段 5 · 局部调整

**优先级顺序**：

1. **HSL 颜色选择**（零风险，效果自然）
2. **`add_local_adjustment`**（线性/径向渐变）
3. ~~`add_ai_mask`~~ ← **不要用**，会卡死目录写锁，见 [坑 9](pitfalls.md#pit-9)

**如果确实需要 AI 蒙版**：让用户在 Lightroom 里手动建好，然后用 `list_masks` 读出**真实**的 mask id，再用 `set_mask_adjustments` 改参数。

> ⚠️ **任何写蒙版参数之前，必须用 `list_masks` 核对名字。**
> `add_ai_mask` 返回的 id **可能是错的**——实测它返回了照片上另一个人脸蒙版的 ID，直接用会**覆盖用户自己做的修图**。

## 阶段 6 · 收尾

| 项目 | 何时做 | 参考值 |
|---|---|---|
| **降噪** | **拿到照片先看 ISO**，高 ISO 就在写影调时一起设 | 见 [坑 18](pitfalls.md#pit-18) |
| 暗角 | 需要压边、突出主体时 | `−10 ~ −20`，别过头 |
| 颗粒 | 想要胶片感 | `GrainAmount 15~25` |

> 💡 降噪**不要等用户放大发现再补**——那会显得你不专业，而且返工更麻烦。

## 阶段 7 · 交付（最容易出事的一步）

### 7.1 导出全尺寸

```
export_photos(destination=..., format="jpeg", quality=100,
              on_existing="overwrite", photo_ids=[id])
```

- **不要传 `width`/`height`**——会把图变成 1000px（[坑 12](pitfalls.md#pit-12)）
- `quality` 参数其实无效，但**输出本来就是最高画质**（[坑 11](pitfalls.md#pit-11)）
- 导出后用 `scripts/imgsize.py` 核实尺寸

### 7.2 与参照文件做 MAD 比对 ← **不可跳过**

**这一步是被一次真实事故教出来的。**

六张照片全部调完、用户逐张确认、统一导出——结果有**三张是错的**。当时的验证方式是「文件大小 + JPEG 画质」，两项都正常，但内容是**会话早期的废弃版本**。

**根因是用户在 Lightroom 里点开了旧快照**，而快照会静默覆盖所有调整，且 SDK 无法检测。详见 [坑 19](pitfalls.md#pit-19)。

**规矩**：

1. 每次用户点头 → 当次导出**另存到不会被覆盖的路径**，作为唯一真相来源
2. 交付前，新导出与参照文件做**逐像素比对**（代码见 [README](../README.md#交付前必须做的验证)）
3. **MAD 应该接近 0**

| MAD | 含义 |
|---|---|
| `0.00` | 逐像素一致 ✅ |
| `2 ~ 10` | 有明显差异 → **先查色温** |
| 尺寸不同 | 裁切/角度被动过 → `CropAngle` 和 `CropTop/Left/Bottom/Right` **都要恢复** |

### 7.3 提醒用户改名

导出默认沿用原文件名（`IMG_0031.jpg`）。**拷回原目录会覆盖原片**——一定要提醒。

## 迭代原则

| 原则 | 原因 |
|---|---|
| **一轮只改 1~3 个参数** | 一次改一堆，你不知道是哪个在起作用 |
| **每轮重新出图 + 重跑直方图** | 用前后数字对比，不靠记忆和感觉 |
| **4~5 轮后收敛** | 收益递减，再调是浪费时间 |
| **别把「电影感」理解成「压暗」** | 实测最常犯的错。压暗 ≠ 氛围 |

---

## 沟通原则

1. **调之前先问方向**，别自己假设。用具体选项让用户选（延续原风格 / 青橙 / 黑白 / 清爽日系…）
2. **主动报告诊断数据**，别只说「调好了」。用户看得到数字才有判断依据
3. **调错了要直说**，并说明**是哪个参数导致的、怎么改**
4. **交付时说清楚**：成品路径、尺寸、原片是否安全、效果存在哪个虚拟副本
5. **每次交付后提醒改名**——避免覆盖原片
